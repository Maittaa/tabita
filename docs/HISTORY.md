# Tabita — подробная история версий

Справочник для глубоких раскопок: что и как сделано в каждой версии (имена классов, ключи JSON, пороги, тесты). Актуальная картина — в HANDOFF.md. Записи не правились задним числом: часть ранних деталей устарела (например, вкладки, значки, Obsidian, провайдер для Sink) — сверяйтесь с кодом.

## Ранние версии (до 5.3): описание файлов на тот момент
- **Model.kt** — ItemType: CHECK, SCALE, NUMBER, DURATION, MULTI, TEXT, MEALS, EXPENSES, BODY, WATER. Source: NONE, HC_SLEEP, HC_STEPS, HC_EXERCISE, HC_RESTING_HR, HC_WEIGHT, OPENSCALE. TemplateItem(id, name, type, plusAllowed, options, unit, min, max, source, hidden, counter). Meal, Purchase, parseCounts/countsToString, waterTemplateItem() (id "water", max = норма в литрах), bodyTemplateItem(), manualKey, srcKey, форматтеры.
- **Repo.kt** — единый data.json (version 3, миграции v1→v2→v3), StateFlow: template, entries, monthNotes, balance, layout. Плитки Tile(id, w, h, small). Цепочка баланса: BalanceAnchor(date, amount, dayNet), balanceOn(date) = последняя фиксация до даты + сумма дневных итогов после неё; ключ JSON "balanceFix" (старый "balance" читается). setValues уважает ручные правки, setBodyDays, latestWeight, бэкап ZIP с фото (writeBackup/importBackup).
- **Health.kt** — Health Connect: сон, шаги, тренировки, пульс покоя, вес; aggregateGroupByPeriod/readRecords; имя пакета‑источника пишется в `<id>!src`.
- **OpenScale.kt** — ContentProvider `content://<pkg>.provider/meta|users|measurements/{userId}`, колонки datetime + values_json (API v3) или legacy weight/fat/water/muscle; разрешение `<pkg>.READ_WRITE_DATA`. **BodyCatalog.kt** — builtin.* → имена RU/EN, иконка, «хорошее» направление, порядок.
- **AppNames.kt** — имя приложения‑источника по пакету; если не резолвится → подпись «из Health Connect» / «из openScale».
- **DayScreen.kt / DayTiles.kt / TileGrid.kt** — экран «День»: плитки как в Pixel Launcher (4 колонки, unit 52dp, gap 8dp), перетаскивание, ресайз рамкой с 4 ручками, анимация, компактные сводки и 7‑дневный спарклайн; кнопки внизу «Пункт», «Все пункты», «Плитки»; плотные ChecksRow, CounterChip (тап +1, долгий — сброс).
- **Blocks.kt** — Питание (сводка + диалог: калории, Б/Ж/У, фото, AI‑калории), Финансы (покупки с ценой за единицу, баланс по дням с ручной правкой), BodyBlock (весы, фоновые иконки 80% прозрачности).
- **Water.kt** — вода: слайдер 0…норма, кнопки, подсказка нормы (30 мл/кг + 0,5 л на час тренировки).
- **StatsScreen.kt / Charts.kt / FinanceCharts.kt** — «Графики»: карточки SeriesCard, BarsCard, BodyCard, DonutCard, FlowCard, NoteCard; тип графика на карточку (LINE/BARS/SMOOTH/WEEKLY/DELTA, линия цели); фильтр, 1/2/3 в ряд, попап; донат и поток по финансам.
- **SettingsScreen.kt** — «Ещё»: Health Connect, openScale, уведомления, AI‑калории, блокировка, оформление (иконка, тема, акцент), язык и валюта, лог, экспорт CSV, бэкап.
- **Theme.kt** (Material You / свой акцент, контуры как в Keep), **Scrollbar.kt**, **Log.kt** (логи в Documents/Tabita/logging через MediaStore, краткий/полный, обработчик крашей), **Prefs.kt**, **Reminders.kt** (AlarmManager, мотивационные фразы), **Ai.kt**, **LockScreen.kt** (биометрия BIOMETRIC_WEAK|DEVICE_CREDENTIAL + PIN, SHA‑256), **MainActivity.kt** (FragmentActivity, вкладки День / Графики / Ещё), **AppIcons.kt**, **I18n.kt + Strings.kt** (EN‑словарь, генерируется).

- **MonthLogic.kt** (5.3) — расчёты «Итогов месяца»: Metric (пункт или вариант списка, MKind CHECK/SCALE/AMOUNT/WATER/OPTION), цели по умолчанию (сон 7 ч, шаги 8000, тренировки 20 мин, оценка 70% шкалы, вода — норма), MonthCfg в Prefs.monthCfg (состав индекса, цели, цель индекса, итог дня rate/index), MonthData: heatRows (уровни 0–3/пропуск), factors (с/без + «накануне», надёжно если ≥3 дней в каждой группе и ≥7 всего), index/indexStats/streaks, goalRows (дни и % против прошлого месяца). Незаполненный день (нет ручных пунктов) — пропуск, а не ноль.
- **MonthScreen.kt** (5.3) — MonthView: карта по дням (тап → день), «Что влияет», «Индекс дня» (настройка — диалог со степперами, без текстовых полей), «Цели». На экране графиков переключатель «Динамика / Итоги месяца» (Prefs.statView). Переход к дню: MainActivity.jumpDate → DayScreen.

- **Группы (5.4)** — Model.kt: GroupKind (CHECKS, VALUES, LISTS, BLOCKS — какие ItemType входят), Group(id, name, kind), TemplateItem.group. Repo: groups StateFlow (JSON "groups"), groupOf, tileIdOf, normalizeGroups (у каждого вида есть группа; дефолтные id checks/values/lists/blocks). Отметки одной группы = одна плитка с id группы (старая плитка "checks" = дефолтная группа); остальные пункты — свои плитки.
- **Порядок (5.4)** — источник правды — порядок плиток. setLayout переупорядочивает шаблон под экран; «Все пункты» (TemplateScreen) показывает groupsInOrder; стрелки: отметки меняются внутри плитки, остальные пункты меняют местами свои плитки (moveItem); двойные стрелки группы отметок — moveTile. Пункт, сменивший группу, встаёт в её конец.
- **Мягкий индекс (5.4)** — пропуски не снижают; галочки по умолчанию «бонус» (отмечено = 1, нет — не считается), MonthCfg.daily — «каждый день» (нет = 0), MonthCfg.weekly — «N раз в неделю». Неполный день (< половины нечековых пунктов индекса) — пустая точка, не идёт в средние/серии. Серии не рвутся пропусками.
- **DayProgress.kt (5.4)** — строка над плитками: что не записано для индекса (чип → открыть пункт), недельные цели, серия дней с записью (1 пропуск в неделю прощается). Reminders.dailyText — вечернее напоминание называет, чего не хватает; при «только если что-то не записано» молчит, если всё записано.
- MonthCfg.heat — выбор строк карты по дням (5.3.1).

- **Самочувствие (5.5)** — Wellbeing.kt: банк блоков WBlock (phq8, gad7, panic, cbi, who5, pss4, isi; тексты Tx ru/en, подсчёт, полосы WBand level 0–3, adviseLevel), Checkup/BlockResult (Repo.checkups, JSON "checkups", data version 4 — миграция добавляет пункт "wb"), WDraft (черновик в Prefs.wbDraft). Prefs.wbPeriod (7/14/30), wbBlocks (по умолчанию 5 блоков = 30 вопросов). WellbeingScreen.kt — вкладка №3: главная, выбор блоков, прохождение по одному вопросу, итог, подробно (график с полосами, «что сильнее всего», дневник за 2 недели до). ItemType.WELLBEING (вид BLOCKS): плитка дня — «через N дн.» / акцент tertiaryContainer «пора» / «пройден»; тап сразу открывает тест (MainActivity.wbStart). В день прохождения entries[date]["wb"]="1". Напоминание id 2 в день чекапа. PHQ-9 взят без 9-го вопроса (PHQ-8) сознательно.

- **Графики (5.6)** — WellbeingCard/WbSeries в StatsScreen: все шкалы чекапа одной карточкой «как весы» (чипы, график выбранной, таблица с полосой и изменением с прошлого прохождения; Prefs.wbSelected). Порядок карточек: Prefs.statOrder (ключи, разделитель \u001F), ordered() — известные по порядку, новые в конце; FilterDialog = список карточек с галочкой и стрелками, «Сбросить порядок».

- **GigaChat (5.7)** — GigaChat.kt: провайдер "gigachat" для калорий по фото. Ключ авторизации (Studio → проект → Настройки API) → POST ngw.devices.sberbank.ru:9443/api/v2/oauth (Basic, RqUID, scope=GIGACHAT_API_PERS) → токен на 30 мин (кэш) → POST api.giga.chat/v1/files (multipart file+purpose=general) → chat/completions с attachments (одно фото на сообщение) → удаление файлов. Обязателен User-Agent. res/raw/russian_trusted_root_ca/sub_ca + res/xml/network_security_config.xml — доверие НУЦ Минцифры только для доменов sberbank.ru и giga.chat. Модели с фото: GigaChat-2-Pro/Max. Пользователь из России: OpenRouter блокирует РФ (Cloudflare), Gemini тоже недоступен.

- **Гликемика (5.8)** — Glycemic.kt: Meal.gi / Meal.gl (JSON "gi","gl"), Meal.glEff = gl ?: gi×carbs/100. Пороги ГИ 55/70, ГН приёма 10/20, ГН дня 80/120. Glycemic.day(meals) → load, avgGi (взвешен по углеводам), peak, score 0–100 (100 − штраф за нагрузку >80 до −40, за ср. ГИ >55 до −30, пики ГН>20 до −15 каждый, всего до −30), unknown. ИИ-промпт просит gi и gl. UI: поля ГИ/ГН в приёме, плашка в сводке, GlycemicDaySummary в блоке «Питание», справка; карточка графиков "gly_<id>"; в CSV столбцы ГН и оценки.

- **Сон (5.8)** — Sleep.kt. Пункт остаётся DURATION + HC_SLEEP (значение — минуты, совместимо с MonthLogic); блок рисуется по source == HC_SLEEP. Подробности из HC в ключе `<id>!sd` (SleepDetail: s/e мс, st = [смещение мин, длит., тип]; типы 0 без сна, 1 REM, 2 лёгкий, 3 глубокий, 4 сон без фаз). Health.kt собирает фазы через Sleep.combine. Ручная правка (`!m`) — показываются только часы, детали игнорируются. Sleep.score: без фаз — длительность ×100; с фазами — длительность 50 + качество 25 (глубокий ≥15 %, REM ≥20 %) + восстановление 25 (эффективность, пробуждения). Норма = MonthCfg.goals[id] ?: 420. Полосы 90/80/60. SleepBlock: кольцо, гипнограмма, фазы с нормами, подсказка о синхронизации. Графики: SleepCard (ключ "num_<id>", как весы): оценка, длительность, фазы (столбики), глубокий, REM, лёгкий, без сна, пробуждения, эффективность, отбой, подъём; Prefs.sleepSelected.

- **Настройки (5.8)** — SettingsScreen: главный экран — группы (Персонализация, Синхронизация, Настройки, Информация) со строками SetRow (иконка, статус); раздел открывается во всплывающем окне (Dialog), содержимое в SectionBody(id). «Экспорт» и «Резервная копия» — раздел "data", журнал — в «О приложении». В тестах настройки сначала открывать раздел (например «Уведомления»).

- **5.9** — Общая оценка самочувствия: Wellbeing.total (псевдоблок id "total", 0–100, полосы 25/50/75), goodness(b, v) = 100×(1−v/max) для «чем больше, тем хуже», иначе 100×v/max; overall = среднее по пройденным блокам; Checkup.overall. TotalCard на главной и в итоге чекапа; в карточке графиков «Самочувствие» первая серия — «Общая оценка». Период вопросов: в текстах метки {p} (последнюю неделю / последние 2 недели / последний месяц) и {half} (ответ PHQ: «Более недели» только для 14 дн., иначе «Более половины дней»); Tx.s(period), Wellbeing.period(); период сохраняется в Checkup.period (JSON "p", старые = 14). Карточка графиков "index" — индекс дня через MonthData.indexOn, линия цели = MonthCfg.target. Серия записей: подпись «1 пропуск на неделе прощён», по нажатию — пояснение. Значки ic_egg («Яйцо», alias IconEgg) и ic_skull («Скелет», IconSkull): fg — плитка 304 px со скруглением в центре 432, bg — размытая плитка, mono — силуэт по цвету.

- **5.10** — Знак влияния на индекс: MonthCfg.negative (JSON "neg") — ключи метрик (id отметки или "<id>:<вариант>"). Минус: CHECK отмечено → 0, не отмечено → null (с «каждый день» → 1); OPTION → 1 − v/лимит (лимит = цель, по умолчанию 1). MonthCfg.withEffect(key, plus?/null, all) — включить с плюсом/минусом или убрать из индекса (минус снимает «в неделю»). MonthData.metrics добавляет варианты списков, явно включённые в индекс/минус, даже если ещё не встречались. UI: EffectChips (＋/−) в «Индекс дня и цели»; в ItemDialog — «Влияние на индекс дня» (не влияет/плюс/минус; для списка — по каждому варианту), effectOf/onEffects передаются из DayScreen (и в TemplateScreen). ItemDialog показывает все группы (выбор группы другого вида меняет тип), «Новая группа» прямо в окне (onNewGroup), полоса прокрутки.

- **5.11** — Repo.moveGroup(id, ±1): группы (с видимыми пунктами) меняются местами, плитки выстраиваются по группам с сохранением порядка внутри; двойные стрелки у каждой группы в «Все пункты». Чекап самочувствия: при удалении результаты (Repo.checkups) остаются, карточка графиков показывается при наличии прохождений; в ItemDialog тип WELLBEING доступен, если его нет в шаблоне (canAddWellbeing), новый получает id "wb". Траты: DonutCard.items (дата + покупка) и prevByCat; CategoryDialog по нажатию на категорию (чипы и строки столбцов): сумма, доля, к прошлому периоду, топ-5 по названиям, все покупки.

- **Тренировки (5.15)** — Workouts.kt: WorkoutKind (15 видов, коды HC ExerciseSessionRecord → вид: силовая 70/81/13, бег 56/57, ходьба 79/82…), WorkoutSession(kind, min, start, title, src, note). Ключи: `<id>!ex` — сессии с часов (Health.kt читает readRecords, dedupe пересечений разных приложений), `<id>!exm` — ручные. Значение `<id>` = засчитанные минуты обоих списков; Repo.recountWorkouts вызывается в setValues; setWorkouts(date, item, list) — ручные (для дней до 5.15 без списка прежние минуты остаются основой). Ходьба не засчитывается, пока Prefs.countWalking = false (переключатель в блоке и в «Часы и весы»; recountAllWorkouts). `<id>!m` — ручная правка итога, как раньше. WorkoutBlock в DayScreen для HC_EXERCISE; плитка показывает виды; карточка графиков — «по видам». RestingHrHint — раскрывающаяся инструкция замера под пульсом покоя, если нет данных из HC или правка вручную.

- **Плитки (5.16)** — только 4 положения: enum TileSize (Repo.kt) FULL (развёрнута), WIDE 4×2, HALF 2×2, MINI 1×2. Repo.Tile.size / snapped(); tiles() приводит старые произвольные размеры к ближайшему. Ресайз точками в TileGrid «перескакивает» между положениями (ширина 1 → мини, 2 → половина, 3–4 → широкая; у широкой тянуть вниз на 2+ клетки → полная, у полной вверх → широкая). В EditBanner — 4 кнопки размера (вместо «Исходный размер»). CompactTileView: WIDE — иконка в круге, название, значение, подпись в строку, график 7 дней справа; HALF — название, значение, подпись (2 строки), иконка фоном; MINI — иконка, значение (до 2 строк), название.

- **Сцепка приёмов (5.17)** — Meal.link (JSON "link"): карточки с одним link — один приём; Meal.unit = link или id. mealUnits(meals) группирует, combineMeals(list) — суммы ккал/БЖУ/ГН и ГИ, взвешенный по углеводам. Glycemic.day считает по приёмам (один пик на сцепку). MealsBlock: при «Добавить приём пищи», если такой вид уже есть (кроме перекуса), — вопрос «Тот же, сцепить» / «Отдельный перекус»; сцепка показывается LinkedMealSummary (шапка с суммами + позиции, каждая открывается). В MealCard — «Один приём с… / Расцепить» или чипы «Сцепить с…» (одноимённые первыми); смена вида у сцепленной позиции её расцепляет. cleanMealText: описание-список ["…","…"] от ИИ показывается через запятую (Ai.kt и Meal.fromJson).

- **Данные для «Подхода» (5.18)** — TrainingProvider.kt: `content://org.maittaa.tabita.training/summary?days=35` → курсор с колонкой "json" `{v, days:[{d, sleep, rhr, steps, ex, w, rate, rmin, rmax}], checkup:{d, overall, blocks:[{id, t, g}]}}`. Читает data.json напрямую, ничего не пишет. Защита: разрешение `org.maittaa.tabita.permission.READ_TRAINING_DATA`, protectionLevel `signature|knownSigner`, сертификат «Подхода» (SHA-256 `a033136d…739720`) в res/values/training.xml. Тест TrainingProviderTest. Приложение тренировок Sink (org.maittaa.sink; раньше Tops org.maittaa.tops и «Подход» org.maittaa.podhod, ключ общий) по этим данным подбирает интенсивность. 5.18.1: до 120 дней, из весов openScale добавлены fat, muscle, bmi.

- **Профиль (5.19)** — Profile.kt: Profile(heightCm, birthYear, sex "m"/"f") в data.json (ключ "profile"; Repo.profile/setProfile; не стирается wipeAll; старая копия без профиля текущий не затирает). Раздел настроек "profile" в «Персонализации» (ProfileBody: поля рост/год, чипы пола, блок «Что считается»). Anthro: bmi, ffmi, ffmiNorm (+6,1×(1,8−h)), fmi, normalWeight (ИМТ 18,5–25), bmr (Миффлин – Сан Жеор, без пола — среднее −78), strideM (0,415/0,413 роста), energy = BMR×1,2 + 0,5×вес×км шагов сверх 3000 + (MET−1)×вес×ч тренировок (ходьба/бег/поход — 0, их дают шаги); weightOn — последний вес до 60 дн. Графики: BodyCard "anthro" «Тело и рост» (ИМТ по весу и росту профиля, FFMI, FFMI норм., FMI, талия/рост; BodySeries.dec, BodyCard.note), SeriesCard "energy_<id>" «Энергобаланс: съедено − расход» (Anthro.balKcal — без «+», иначе оси/тренд дают «−+»), в карточке шагов — км. TrainingProvider: "profile":{h,age,sex}, по дням ffmi, kcal, tdee; bmi считается по профилю. ordered(): новая карточка встаёт после соседа по умолчанию, а не в конец.
- **Проверка ответа ИИ (5.19)** — промпт требует items [{name,g,kcal,protein_g,fat_g,carbs_g}] и правила (вода 0, брендовые продукты — по этикетке, растворимые напитки ≈0 белка, Б+Ж+У ≤ веса, ккал = 4Б+4У+9Ж). Ai.parse: итоги — суммы позиций после Ai.sanitize (Б+Ж+У ≤ g, энергия БЖУ ≤ ккал×1,25+3 — иначе пропорционально уменьшаются); ГН пересчитывается по исправленным углеводам; старый формат (только итоги) тоже проверяется. Тест AiSanityTest (случай Herbalife: 3 г порошка, белок 4 г).

- **Совместимость (5.19.1)** — Compat.kt: dynamicColors (API 31), themedIcons (33), hcBuiltIn (34), sinkLink (31, knownSigner).
